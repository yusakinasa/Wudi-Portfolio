## 一、开始前的准备

使用 Google、GitHub、OpenAI、YouTube、Hugging Face 等国际服务时，首先要保证当前网络环境能够正常访问目标网站。

### 代理软件在做什么

代理服务通常提供一个订阅地址，代理客户端负责解析其中的节点与规则，再按配置转发网络流量。常见模式包括：

- **Direct（直连）**：流量不经过代理，直接访问互联网。
- **Rule（规则）**：根据规则决定哪些请求使用代理、哪些请求直连，通常最适合日常使用。
- **Global（全局）**：所有请求都经过代理。
- **TUN（虚拟网卡）**：通过虚拟网络设备接管系统流量，使浏览器之外的软件也能使用代理。
- **LAN（局域网连接）**：允许局域网内的其他设备连接本机代理。

### 一般配置流程

1. 从自己信任且合法合规的服务商处获取订阅地址。
2. 安装适合当前操作系统的代理客户端，例如 Clash Verge 类客户端。
3. 在客户端的“订阅”页面导入自己的订阅地址。
4. 选择合适的节点和规则模式。
5. 开启系统代理后，测试目标网站能否正常访问。

> 原 PDF 中包含一个可直接使用的订阅地址。公开版本不收录该地址，以免泄露访问凭据或导致订阅被滥用。不要把个人订阅地址、API Key、Cookie 或登录令牌提交到公开 Git 仓库。

### 使用代理时的注意事项

- 不要同时开启多个代理客户端，避免端口或路由冲突。
- 节点延迟只是参考指标；能否稳定访问目标服务更重要。
- 如果订阅长时间未更新，应从服务商处重新获取配置。
- 关机前可以先关闭系统代理。如果异常关机后无法正常上网，可尝试重新打开客户端，再关闭系统代理。
- 某些国内服务在代理环境下可能变慢；遇到问题时检查规则或临时切换为直连。

## 二、Google 账号与常用网站

Google 账号可以用于 Gmail，也被许多国际网站用作第三方登录方式。可以通过 [Google 账号注册页面](https://accounts.google.com/signup)创建账号，并妥善保存密码、恢复邮箱和双重验证信息。

常用入口：

- [Google 搜索](https://www.google.com/)
- [Google Scholar](https://scholar.google.com/)
- [GitHub](https://github.com/)
- [YouTube](https://www.youtube.com/)
- [Google Chrome](https://www.google.com/chrome/)

在 Chrome 中登录 Google 账号后，可以同步书签和设置，也能更方便地使用支持 Google 授权的网站。是否登录浏览器本身取决于个人隐私和同步需求，并不是使用 Codex 的必需条件。

## 三、先认识 ChatGPT

ChatGPT 是 OpenAI 提供的 AI 产品。它可以围绕文本、图片和文件完成多种任务，例如：

- 起草、改写和总结内容；
- 将复杂主题解释为更容易理解的版本；
- 在可用时搜索网络并整理信息；
- 生成或分析图片；
- 辅助编写、解释和调试代码。

可以从 [ChatGPT 网页版](https://chatgpt.com/)开始体验。账号注册方式、地区支持、客户端平台和可用功能可能变化，应优先查看官方页面，而不是依赖过时的第三方教程。

## 四、Codex 与普通对话有什么不同

普通聊天的典型流程是：把问题或代码复制到对话框中，获取回答后，再手动把结果放回项目。如果项目很大，模型往往只能看到用户复制出来的一小部分内容。

Codex 更像一个能进入工作现场的 Agent。获得授权后，它可以围绕当前工作目录：

- 检查项目结构和已有代码；
- 读取、创建和修改文件；
- 运行构建、测试、格式化和类型检查命令；
- 根据执行结果继续定位和修复问题；
- 展示操作过程、终端输出和最终改动，供用户审查。

可以把普通聊天想象成“站在工地外的顾问”，每次都要把砖瓦搬出去给他看；Codex 则是在权限边界内进入工地，观察整体结构并直接参与工作。

### 能力不等于无限权限

Codex 的实际能力取决于当前使用形态、权限设置、沙箱、可用工具和网络配置：

- 本地工作区与云端任务的运行环境不同。
- 文件写入、命令执行和联网能力可能受权限限制。
- 一些操作会要求确认，尤其是可能修改工作区或访问工作区之外的位置时。
- 即使任务已经通过测试，用户仍应审查重要代码和高风险操作。
- 对重要项目，建议在开始前创建 Git 提交或分支，确保改动容易回退。

## 五、需要理解的基本概念

### AI Agent

Agent 不只是回答问题，还会为了完成目标自行判断下一步、调用工具、执行操作并检查结果。Codex、Claude Code 等都属于这一类工具。

### Context、History 与 Memory

- **Context（上下文）**：模型当前回答时能够看到的信息，包括当前问题、前文、指令、文件和工具结果。
- **History（历史）**：当前会话中已经发生的对话和操作记录。
- **Memory（记忆）**：被保存下来、可供后续会话使用的信息，例如长期偏好、工作方式或项目背景。具体能力取决于产品和设置。

### Prompt cache

当大段提示词或上下文被重复使用时，系统可能缓存重复部分，以降低延迟或计算成本。缓存机制由服务提供方实现，并不等同于模型永久记住了内容。

### LLM 与 API

- **LLM（大语言模型）**：能够理解和生成自然语言的模型，是聊天产品与 Agent 的核心能力来源。
- **API（应用程序接口）**：允许程序通过代码向模型发送请求并接收结果。

### Token、推理强度与 Rate limit

- **Token**：模型处理输入和输出时使用的计量单位，会影响上下文容量、用量和费用。
- **Reasoning effort（推理强度）**：控制模型在回答或执行任务时投入的推理资源。更高不一定适合所有任务，简单操作通常无需最高强度。
- **Rate limit（速率限制）**：服务在一定时间内允许的请求数或 Token 数。超过限制后通常需要稍后重试。

### Sandbox

Sandbox（沙箱）用于限制程序可以读取、写入和执行的范围。它不是“什么都不会影响”的绝对隔离层；实际边界应以当前权限提示和配置为准。

### `AGENTS.md`

`AGENTS.md` 是放在项目中的持久说明文件，可以告诉 Codex：

- 项目结构和重要目录；
- 构建、测试与检查命令；
- 编码规范和命名习惯；
- 禁止修改的内容；
- 完成任务时必须满足的验证条件。

Codex 会按目录层级读取适用的说明。可以用 `/init` 生成初始文件，但生成后仍应根据项目实际情况编辑。

### Skill

Skill 是为 Agent 预先定义的一套专门能力或操作流程，规定什么时候使用、需要读取哪些资料、如何调用工具以及怎样验证结果。常见用途包括网页检索、PDF 处理、表格编辑和固定的项目维护流程。

## 六、Codex 的几种使用形态

### 桌面应用

桌面应用提供图形界面，适合不熟悉终端的用户。通常可以选择工作目录、模型和推理强度，并直接查看文件改动和执行过程。可从 [ChatGPT 下载页面](https://chatgpt.com/download/)查看当前支持的平台。

### Codex CLI

CLI 在终端中运行，适合熟悉命令行、需要直接处理本地项目或把 Codex 接入脚本的用户。它可以在当前目录中检查代码、修改文件、运行命令和进行代码审查。

### IDE 集成

Codex 也可以集成到 VS Code 等开发环境中，在编辑器侧栏里提供上下文相关的辅助。不同 IDE 的支持情况会变化，应从官方文档确认。

### 云端任务

云端形态可以在隔离环境中执行任务，并与 GitHub 仓库协作。它与直接操作本地工作区的 CLI 不是同一种运行环境，网络、依赖和权限也可能不同。

## 七、安装并启动 Codex CLI

安装方式会随平台更新。OpenAI 官方目前提供安装脚本、npm 和 Homebrew 等方式，完整步骤参见 [Codex CLI 官方指南](https://learn.chatgpt.com/docs/codex/cli)。

如果使用 PDF 原稿中的 Node.js/npm 路线：

1. 从 [Node.js 官网](https://nodejs.org/en/download)安装适合当前系统的 Node.js。
2. 打开 PowerShell、Windows Terminal 或其他终端。
3. 安装 Codex CLI：

```bash
npm install -g @openai/codex
```

4. 进入希望 Codex 处理的项目目录：

```bash
cd path/to/your-project
```

5. 启动 Codex：

```bash
codex
```

6. 第一次启动时，按照界面提示选择登录方式、模型与推理强度。若询问是否信任当前文件夹，应先确认目录正确，再决定是否信任。

## 八、第一次使用的推荐流程

不要一开始就让 Codex 大范围改造项目。更稳妥的顺序是：

1. 确认终端当前所在目录。
2. 用 Git 保存当前状态。
3. 先让 Codex 解释项目结构，例如：“请阅读这个项目并说明各目录的作用，不要修改文件。”
4. 提出一个范围明确的小任务。
5. 观察它准备读取哪些文件、运行哪些命令。
6. 检查生成的 diff 和测试结果。
7. 确认结果正确后再提交改动。

一个更容易得到稳定结果的任务描述，通常会说明：

- **背景**：当前项目是什么、已有约束是什么；
- **目标**：这次只需要完成什么；
- **边界**：哪些文件或行为不能改；
- **验证**：完成后要运行哪些检查。

## 九、常用命令

在 Codex CLI 中输入 `/` 可以查看当前版本实际支持的命令。常用命令包括：

- `/model`：选择当前会话使用的模型与推理强度。
- `/status`：查看当前会话配置和状态。
- `/permissions`：查看或调整当前会话允许的操作范围。
- `/init`：在当前目录生成 `AGENTS.md` 初始模板。
- `/compact`：将较长的历史对话压缩为摘要，释放上下文空间。
- `/review`：对工作区改动执行专门的代码审查。
- `/diff`：查看已暂存、未暂存和未跟踪的文件改动。
- `/mention <路径>`：把特定文件加入当前对话上下文。
- `/mcp`：查看已连接的 MCP 服务和工具。

命令会随着版本和使用界面变化。使用时以 `/` 菜单和[官方命令参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)为准。

## 十、计划、审批与审查

### 计划模式

计划模式适合先分析需求和代码，再决定具体改动。它通常用于复杂任务的需求澄清和实现设计，但具体能否执行命令、是否只读，仍取决于当前产品与权限配置。

### 审批

当 Codex 准备执行超出当前授权范围的操作时，可能会请求用户批准。批准前应检查：

- 操作目标是否是预期文件或目录；
- 命令是否可能覆盖或删除数据；
- 是否需要联网、安装依赖或访问工作区之外的位置；
- 是否存在范围更小、更容易回退的做法。

### 最终审查

完成任务后至少检查：

1. `git diff` 中有哪些文件发生变化；
2. 是否出现无关改动或凭据泄露；
3. 构建、测试和类型检查是否通过；
4. 文档与实际行为是否一致；
5. 是否需要人工体验关键页面或流程。

## 十一、账号、额度与 API

Codex 的可用功能可能与 ChatGPT 账号方案、组织策略、地区、客户端版本和当前活动有关。API 用量与 ChatGPT 订阅也不是同一套计费体系。

由于价格、模型名称和额度变化很快，本文不保留 PDF 中的具体价格比较表，也不推荐非官方代充或来源不明的 API 中转服务。需要付费时，优先使用官方渠道，并在提交任何密钥前确认服务提供方和隐私条款。

## 十二、继续探索

完成基础配置后，可以尝试让 Codex：

- 阅读一个陌生项目并绘制结构说明；
- 修复一个能够稳定复现的错误；
- 为已有功能补充测试；
- 把重复操作整理为脚本或 Skill；
- 根据团队规则完善 `AGENTS.md`；
- 在提交前执行代码审查并解释风险。

最重要的能力不是记住所有命令，而是学会给出明确目标、控制权限边界、检查执行证据，并保留可回退的工作状态。
